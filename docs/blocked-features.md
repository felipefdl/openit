# Blocked features

Dependency limitations and unresolved feasibility checks from the [application architecture](specs/application-architecture.md). GPUI Kit API findings refer to 0.6.1. A pending validation is not a confirmed upstream limitation.

| Feature | Why it cannot be completed | What is needed |
| --- | --- | --- |
| Preserve the same reading position when switching Markdown preview/edit modes | gpui-base keeps Markdown block source spans private and exposes no caret-preserving editor scroll API. The prototype demonstrated block alignment in both directions, but offsets within blocks need a line estimate and editor reveal must wait for first layout. OpenIt retains each mode's state but does not align the passage across modes. | Public source anchors and caret-preserving scroll APIs in gpui-kit. No fork, vendored copy, or second Markdown parser. |
| Select the next occurrence with Cmd+D / Ctrl+D | gpui-kit has no select-next-occurrence action. Arbitrary multicursor selection mutation is private, and the public `set_selected_range` removes additional cursors. A keybinding alone cannot provide additive occurrence selection. | An upstream action or public additive-selection API. No fork or separate selection engine. Built-in cursor addition and rectangular selection remain supported. |
| Safely render SVG images from documents | GPUI's `SvgRenderer` uses usvg defaults whose `<image href>` resolver reads local files. OpenIt cannot enforce document resource permissions through that default resolver, so it shows a placeholder. | An exposed configuration point to disable the resolver before rendering untrusted SVG. |
| Add Markdown preview end spacing independently of source syntax | TextView exposes viewport styling but not internal list content padding. OpenIt appends a preview-only HTML break as a spacing workaround and keeps the preview status bar in normal flow. Unclosed code fences or HTML blocks can swallow the spacer, and preview selection can include it. | A public TextView API for styling the internal document list's content padding. |
| Configure Markdown heading colors | gpui-base does not expose heading colors through `TextViewStyle`. | An upstream heading-color styling API. |
| Center an HTML block in the Markdown preview (`<p align="center">`, `<div align="center">`, `style="text-align: center"`) | gpui-base's HTML converter reads only `width`, `height`, and mark colors from element attributes; `align` and `text-align` are dropped, and its paragraph node has no alignment field, so the content renders left-aligned. Only table columns carry alignment. | Upstream parsing of `align` / `text-align` on block elements into a paragraph alignment rendered with `text_center` / `justify_center`. No fork; a local block plugin would re-implement HTML rendering for that subset and diverge from gpui-base's rendering and selection. |
| Render every PDF construct | `hayro` skips knockout groups, some blend and isolation cases, and non-embedded CID fonts; affected elements render wrong or missing while the rest of the page renders. Text runs without a `ToUnicode` map have no text layer. | Upstream hayro support for those constructs. No PDFium, no native library. |
| Convert CJK text encoded through a predefined CMap | `pdf-inspector` reads the predefined CMaps from a directory named by `PDF_INSPECTOR_BCMAPS_DIR` (or its own source tree at build time); a distributed binary has neither unless packaging sets the variable. `Identity-H` fonts are unaffected. | A packaging step that ships the CMap directory and sets the variable, or an upstream option to embed the CMaps in native builds. |
| Open HEIC, HEIF, and AVIF images | No permissively licensed pure-Rust decoder exists: `libheif` is LGPL-3.0 and `image`'s AVIF decoder links C `libdav1d`. Both fail the license allow-list or the no-system-library rule. | A permissive pure-Rust decoder, or a contained platform decoder (ImageIO on macOS, WIC on Windows) accepted as a per-platform difference. |
| Open schema completions on demand with Ctrl+Space | gpui-base requests completions only from its `pub(crate)` insert-time trigger; there is no public action or method that opens the menu at the caret, and gpui-kit binds no key for it. Schema completions appear while typing (a `"` inside an object) and cannot be summoned otherwise. | An upstream public trigger-completions action or `EditorState` method. No fork; a keybinding alone has nothing to call. |
| Preview Markdown in Finder through a Quick Look extension | macOS 15 dropped legacy `.qlgenerator` plugins, so the route is an app extension whose principal class is Objective-C. A Rust appex (`objc2`) or a Rust static library called from Swift both need unsafe code, which the workspace `unsafe_code = forbid` rule covers for every owned crate. The remaining route is a Swift `QLPreviewProvider` shelling out to a Rust helper, plus a custom macOS sign and package script because cargo-packager 0.11.8 cannot place, entitle, or seal a nested `.appex`. That cost is not worth a static Markdown preview with no local images (the extension sandbox sees only the previewed file). | A GPUI-side integration route that keeps the extension in Rust without unsafe code in owned crates. Until then, Quick Look stays out of the roadmap. |
